# Flink 内核 + Paimon 刻意练习学习方案

> 本方案是 `roadmap/flink-paimon-roadmap-24weeks.md`（内容路线）的**方法论执行层**：roadmap 回答"学什么、按什么顺序"，本方案回答"每次坐下来具体练什么、怎么算成功、反馈从哪来"。
> 方法论依据：安德斯·艾利克森《刻意练习》（标注出处章节）。
> 学科类型判定：**输出创作型 + 知识推理型混合**——这个领域的杰出者是在"排查生产故障、写出被社区接受的代码、白板讲清机制"时表现出杰出的（第2章"杰出者做什么"判定法），所以练习对象是这三件事，而不是"读源码"本身。

---

## 0. 诊断快照

- **终点画面**：45 分钟白板讲透"一条数据从 Kafka 进入 Flink，落 Paimon，再被 StarRocks 查到"的完整生命周期，以及每一步可能出什么故障；扩展题：同一数据派生 embedding 进向量库支撑 RAG 时，一致性与新鲜度如何保证（roadmap W28 终极自测）；2028-11（32 岁）前完成"数据基础设施 / AI 数据底座工程师"一跳。
- **当前水平**：3 年大数据 + 3 年 Java，有工程经验但无 Flink 内核 / Paimon 源码级经验（待验证）。**薄弱自查未填** → 用 W1 基线自测补上（见练习 8），后续随日志滚动修正。
- **时间预算**：工作日 1h × 5 + 周末 3h × 2 ≈ 11h/周；截止 2027-05 下旬（W28 结束；2026-11-12 roadmap 已扩充至 28 周，新增阶段 5「AI 数据底座」W17–20）。低于 8h/周则整体顺延 25%（roadmap 规则）。
- **反馈资源**：无固定导师；范本 = Flink 2.3.0 / Paimon 官方源码与文档、VLDB 论文、社区经典深度文；同伴 = GitHub 社区（maintainer 的 PR review 是高质量的"延迟导师"，第4章）+ 文章读者评论。

## 1. 技能目标（能做什么清单）

**终点目标**：不看任何资料，45 分钟白板讲透端到端数据生命周期 + 每步故障模式与解法；同时拥有 6–8 篇深度文、1 个开源项目、1 个 Apache PR 作为能力证据。

**阶段目标**（与 roadmap 各阶段里程碑一一对应，全部是"能做"句式）：

- 阶段 0（W1，本周）：能本地起 mini-cluster，在 `keyBy` 后打断点，口述调用栈从算子一路回溯到 `main()` 的关键帧；能说清 Flink 2.0 三大变化。
- 阶段 1（W2–4）：不看资料画出"一条数据从 `main()` 到 TaskManager 执行"的完整链路图，并讲出每个组件为什么存在。
- 阶段 2（W5–8）：从源码层面讲清 barrier 从哪发出、怎么流动、非对齐时数据去了哪、RocksDB 增量快照为什么快；写出第 1 篇故障排查深度文。
- 阶段 3（W9–11）：拿到任意反压作业，20 分钟内定位瓶颈算子并给出 3 种以上解法及适用条件。
- 阶段 4（W12–16）：能回答"为什么 Paimon 用 LSM 而 Iceberg 用 COW/MOR"；对着参数表解释每一次 compaction 调优决策的权衡。
- 阶段 5（W17–20，AI 数据底座）：能讲清向量库与 Paimon 在存储设计上的同构与差异；搭出最小 RAG 数据管线，并能指出删除同步与一致性风险点。
- 阶段 6（W21–24）：GitHub 上有陌生人能一键跑起来的湖仓项目（含 RAG 数据管线模块）；首个 PR 已提交。
- 阶段 7（W25–28）：终极白板自测通过；6–8 篇文章发布（含 1–2 篇 AI 数据底座主题）。

## 2. 杰出范本与心理表征

**范本材料**（按维度选定）：

| 维度 | 范本 | 用法 |
|---|---|---|
| 源码 | Flink 2.3.0（`flink-runtime`、`flink-streaming-java`）、Paimon 源码（checkpoint / compaction 模块） | 预测-断点验证（练习 1） |
| 文章 | 社区经典深度文：W8 前选定 1 篇 Flink checkpoint 佳作、W16 前选定 1 篇 Paimon LSM 佳作（候选来源：阿里/美团/字节技术博客、roadmap 参考资料区） | 富兰克林复现（练习 2） |
| 论文 | VLDB《Disaggregated State Management in Apache Flink 2.0》 | W7 精读，先自问 3 个问题再读 |
| 代码 | Paimon 官方示例 / 社区湖仓项目（W16、W20） | 自己先设计再对比 |

**复现-对比方式（富兰克林法，第5、6章，三个维度分开练）**：

1. **源码维度——"预测-断点验证"**：这是 roadmap"断点跟数据走"的自带反馈版本。动手断点前，先在笔记里写下预测："这条数据会经过 A → B → C，B 里会做 X"。然后断点实测。**预测与实际的每个分岔点就是心理表征的缺口**（第3章），记录进练习日志——这是本方案最核心的反馈回路。
2. **文章维度**：对选定范文，先列出每节的内容线索（不写正文）→ 隔 2 天凭线索自己重写 → 逐节对比：我的论证浅在哪？图示差在哪？结构为何那样排？一次只攻一个维度（结构 → 论证深度 → 图示表达，第6章富兰克林分维度练习法）。
3. **代码维度**：W16 湖仓 demo、W20 开源项目，先自己写设计与骨架，再对照官方示例/优秀社区项目，diff 设计决策（命名、边界处理、容错），记录差距。

**心理表征的终点形态**（第3章）：看到一条报错/一个参数，脑中自动浮现"这背后是哪段链路、哪种状态、哪种取舍"——即长期记忆中的组块网络。本方案所有练习都在服务这件事。

## 4. 练习设计（甜蜜点清单）

> 每周配比建议：工作日 1h = 练习 1 / 5 / 6 / 8 轮换（按 roadmap 当周主题）；周末两个 3h = 练习 3 / 2 / 7 + 当周产出物写作。难度自检：轻松 = 加难，绝望 = 减难，"费劲但够得着"才对（第1、2章）。
>
> **AI 阶段（W17–20）配比说明**：练习 1 的预测-实测法同样适用，但对象从 Java 源码换成 API 行为（faiss/pgvector 实验：先预测查询结果与性能，再实测记录偏差）；练习 3 故障实验室加入"向量-源文档不一致"复现；练习 7 设计对比复现用于 RAG 管线 demo（对比 LlamaIndex / LangChain 的参考摄取架构）；练习 4/5 的题库使用面试清单新增的 4 道 AI 题。

| 练习 | 练什么 | 成功标准 | 反馈来源 | 单次时长 |
|---|---|---|---|---|
| 1. 断点追踪（预测-验证式） | 当周主题的调用链/数据流 | 每次至少发现并解释 1 个预测分岔点；随周数增加预测命中率上升 | 断点实测调用栈 vs 事前预测笔记 | 30–40 分钟 |
| 2. 富兰克林文章复现 | 单维度：结构 / 论证深度 / 图示 | 复现稿与原文逐节对比，差距清单 ≤5 条；下一轮同维度差距不复发 | 原文逐节 diff | 40 分钟 × 多天（跨周末） |
| 3. 故障实验室 | W8/W11/W16 制造指定故障（慢 checkpoint / 反压 / 状态膨胀 / compaction 风暴）并排查 | 限时定位 + 解法 + 实验记录（注入什么、看到什么、改了什么、指标前后） | **注入的故障就是标准答案**——天然自带反馈 | 45–60 分钟（周末） |
| 4. 白板录音自测 | 阶段里程碑题 + roadmap 面试清单题 | 15 分钟讲清一题；回听后写下自评修正清单 | 录音回放 + 对照官方文档/源码 | 25 分钟（讲 15 + 回听 10） |
| 5. 间隔自测 | 已学过的面试清单题重测（当晚/隔天/三天/一周，第6章拼字大赛研究：以测代读） | 旧题正确率不衰减，错题进针对性微练习 | 作答 vs 文档/源码核对 | 15 分钟（穿插在热身后） |
| 6. 编码微练习 | watermark 三件套 / merge engine 场景 / compaction 参数实验 | 用例通过 + 能解释每个结果的语义 | 运行结果 + 边界用例 | 30–40 分钟 |
| 7. 设计对比复现 | W16/W20 先自己设计湖仓 demo，再对比官方/社区实现 | 差距清单（命名/边界/容错）≥3 条并逐条消化 | 范本代码 diff | 40 分钟 |
| 8. W1 基线自测（一次性） | 用 roadmap W23 面试清单 10 题摸底 + 薄弱自查 | 每题按"能讲/模糊/空白"三档标记，产出初始技能树"当前水平"列 | 作答录音 + 文档核对 | 45 分钟（周末拆两段） |
| 9. 社区输出 | 文章发布、PR 提交 | 文章 ≥1 条实质互动；PR 获 maintainer 回复 | 读者评论 / PR review（延迟导师） | 不计入单次专注练习 |

## 5. 反馈与记录：练习日志

日志文件：`practice/练习日志.md`（已建好，直接追加）。

每次练习后记一行：`日期 | 练习内容 | 暴露的错误（具体到环节，不写"状态差"）| 明天的针对性调整`。

配套规则：
- 日志顶部维护"**当前唯一焦点**"（来自上次 Fix it），下次练习的热身 5 分钟先看它（第6章三个 F）。
- 每周日花 10 分钟把本周"暴露的错误"归类（概念不清 / 链路断点 / 手误 / 场景误判，参照知识推理型错题四分类），**同一类错误连续三次不犯才算清除**。
- 里程碑自测的录音转写要点、预测分岔点清单，附在当周日志条目下方。

## 6. 里程碑与动机机制

- **固定练习时段**（第6章：固定时段绕过"今天练不练"的意志消耗）：工作日建议锁定早上 7:30–8:30 或晚上 21:00–22:00 二选一，雷打不动；周末上午各 3h，拆成 3 × 50 分钟专注块，块间休息 10 分钟。**单次专注 ≤1 小时**（铁律 5）。⚠️ 具体时段需你本周定死并填入下方空格：工作日 ____ 点–____ 点；周末 ____ 点–____ 点。
- **干扰清除**：手机放到另一个房间（或勿扰 + 番茄钟）；IDEA 全屏，微信/邮箱退出登录。
- **同伴/社群**：文章发到掘金/知乎接受评论；GitHub issue 与 maintainer 互动；如能找到 1 个同方向学习者互相抽查面试题更好（选目标一致的，第6章社会动机）。
- **看见进步**：roadmap 每周打卡表 + 练习日志双记录；每 4 周回听一次 W1 基线录音——进步的可听证据（第6章丹计划数据化）。
- **阶段奖励**（先和自己签好约）：
  - 阶段 0（W1）：环境全通 + 第一篇笔记发布 → 一顿好的
  - 阶段 2（W8）：第 1 篇深度文发布 → 提前兑现心愿清单中 ¥500 以内一项
  - 阶段 4（W16）：湖仓 demo 跑通 → 周末半天彻底休息
  - 阶段 5（W20，AI 数据底座）：RAG 数据管线 demo 跑通 → 提前兑现心愿清单中 ¥300 以内一项
  - 阶段 6（W24）：首个 PR 提交 → 对外自称"Apache contributor"（身份认同，第6章）
  - 阶段 7（W28）：终极白板通过 → 投出摸底简历，兑现跳槽启动
- **睡眠**：睡眠是练习的一部分（第6章）——熬夜赶进度周视为无效练习。
- **停滞预案**（精简版，详见对话内停滞协议；出现"练了没进步/想放弃"时执行）：
  1. 稍微加压暴露弱点（提速/限时/更难的环境）→ 2. 把弱点定位到可练的最小单元（拒绝"我源码看不懂"这种结论）→ 3. 针对最小单元设计微练习 → 4. 仍无效就换方向，不加大强度（第1章）。
  - 判断推得太远：越练越差、厌练 → 退回"能做对"的水平重新小幅递增（第1章迪蕾节拍器法）。
  - 想放弃协议：先恢复到停滞前水平，再决定放不放弃（第6章布鲁姆研究）。
  - 练习 1–2 个月新鲜感消退、开始找借口缺课 = 新年决心效应的正常曲线，不是"不适合"——回到固定时段 + 一个小里程碑 + 同伴，不自责。

## 与 roadmap 的关系（一页纸总览）

- roadmap = **课程表**（学什么、什么周、产出什么）；本方案 = **训练法**（每次坐下怎么练）。
- 周节奏模板：工作日 5 × 1h（练习 1/5/6/8 轮换）+ 周末 2 × 3h（练习 3/2/7 + 产出物写作）≈ 11h，对齐 roadmap 时间预算。
- 每个阶段结束：跑该阶段里程碑自测（练习 4 形式）→ 通过则在 roadmap 打卡表记录 → 未通过则从日志错误分类中找最小单元补练，不顺延阶段（阶段目标比周历优先）。
